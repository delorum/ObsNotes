# Общий список пустых маркеров

Список находится в хранилище: `Скрипты/Настройки/Сжатие дневника.md`, раздел `## Пустые маркеры`.
Это один источник для ObsNotes и команды Obsidian «Удалить лишние пустые строки» по Ctrl+`.
Точная привязка хоткея проверена в `.obsidian/hotkeys.json`: QuickAdd вызывает
`Скрипты/QuickAdd/removeExtraEmptyLines.js`, затем `Скрипты/Modules/emptyLinesRemoveUtils.js`.

Каждая строка `- значение` внутри указанного раздела добавляет маркер. Например:

```markdown
## Пустые маркеры

- свой маркер
```

Регистр, повторения и пробелы по краям не имеют значения. Точки и запятые допустимы как
самостоятельные маркеры. Пример в коде, frontmatter и строки других разделов настройки
не входят в список. Совпадение относится ко всей строке заметки: слово внутри предложения
и маркер с текстом непосредственно под ним сохраняются. Очистка ObsNotes защищает
frontmatter, код и callout, сохраняет LF/CRLF и якоря.

Полный исходный список перенесён из Obsidian без добавлений и сокращений: 28 маркеров.
Он больше не дублируется в Java или JS. Меняйте его прямо в файле хранилища;
Syncthing доставит изменения на другое устройство. Оба клиента перечитывают файл перед
каждой операцией сжатия, без кеширования списка и пересборки приложения.

Пустой раздел списка отключает удаление маркеров. Если файл отсутствует, словесные маркеры
также сохраняются; сжатие пустых строк и очистка таймстампов работают. Файл без нужного
раздела, повторяющийся раздел или ошибка чтения останавливают операцию с сообщением
об ошибке, сохраняя исходные файлы. ObsNotes читает настройки по точному пути в файловой
очереди; хранилище не перебирается.

После обновления самого JS-модуля один раз перезапустите Obsidian или повторно запустите
`initUtils`. После этого изменения списка подхватываются на следующем Ctrl+` автоматически.

Проверка согласованности реального файла (из папки хранилища; исходники ObsNotes отдельно):

```sh
javac -cp /path/to/ObsNotes/core/build/classes/java/main -d /tmp/obsnotes-cleanup-parity /path/to/ObsNotes/tools/CheckCleanupRules.java
OBSNOTES_CLEANUP_CHECK_CP=/path/to/ObsNotes/core/build/classes/java/main:/tmp/obsnotes-cleanup-parity node Скрипты/Tests/diaryCleanupMarkers.test.cjs
```

Проверка только читает настройки. Остальные сценарии JS используют вымышленные заметки;
тесты ядра проверяют передачу пользовательских правил в перенос внутри дня, между днями
и удаление, а также сохранность исходных снимков и обычного редактирования.
