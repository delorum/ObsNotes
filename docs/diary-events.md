# Совместимость связей Obsidian и ObsNotes

Корень — якорь в конце тела и следующий за ним callout `Дополнения к событию` с вызовом `Скрипты/Dataview/outLinkInfo`. Один якорь без callout остаётся кандидатом. У блока может быть несколько ведущих wiki-ссылок на родителей, в том числе несколько ссылок на одной строке. Текст, который уже имеет родителей, также может стать промежуточным корнем.

Ctrl-8 и ObsNotes записывают новые связи с путём файла корня, в том числе внутри одного дневника. При переносе дополнения в другой день ObsNotes разворачивает старые ведущие ссылки `[[#^якорь]]` в пути исходной заметки, сохраняя якорь и подпись. Уже сохранённые корни защищены от переноса между днями, поскольку их входящие ссылки содержат исходный путь.

В хранилище `Скрипты/Modules/Дневник/diaryEventUtils.js` содержит общий разбор для Ctrl-8 и Dataview `outLinkInfo`. Ctrl-8 работает с целым блоком под курсором, включая ведущие ссылки и собственный callout. Меню позволяет сделать блок корнем, добавить родителя, заменить или удалить отдельную связь, снять корневую роль и удалить ведущие ссылки на неё в текущем файле. Существующие корни идут перед кандидатами; скрытые подсказки не становятся кандидатами, а наличие родителей не исключает запись. Назначение корня и добавление ссылки выполняются одной транзакцией редактора. Если файл изменился во время выбора, действие не применяется.

## Автоматические проверки

Выполните из репозитория приложения, указав путь хранилища в следующей команде:

```sh
./gradlew :core:classes
javac -cp core/build/classes/java/main -d /tmp/obsnotes-events tools/CheckDiaryEvents.java
```

Затем из корня хранилища:

```sh
OBSNOTES_EVENTS_CHECK_CP=/path/to/ObsNotes/core/build/classes/java/main:/tmp/obsnotes-events node --test Скрипты/Tests/diaryEvents.test.cjs
```

Без переменной окружения обычные JS-тесты работают самостоятельно, а две проверки с Java пропускаются. Тесты загружают настоящие JS-модуль, QuickAdd-скрипт и Dataview-скрипт в VM с моделями редактора/хранилища. Личные заметки не читаются и не меняются. Двусторонний сценарий создаёт временные вымышленные файлы, проверяет результат настоящим `Events`/`EditorParts`/`VaultRepository` и удаляет их после проверки.

Проверяются создание корня, сохранение существующего якоря, цепочки, несколько родителей, замена/удаление одной связи, снятие корня и входящих ссылок только в текущем файле, LF/CRLF, пустые строки, таймстампы, код, фильтры подсказок, одинаковые подписи, курсор, отмена и внешние правки во время выбора. Для набора Markdown-примеров сравниваются реальные смещения блоков, подписи, родительские пути, корни и порядок кандидатов Java/JS. Отдельно проверяется рендеринг дополнений для обоих родителей, точное совпадение пути и ID, отсутствие ложных совпадений по подстроке/inline/code и сохранение вложенного callout.

Проверка выполняет настоящие обработчики с моделями Obsidian API; открытие меню и визуальное оформление внутри запущенного Obsidian этим не проверяются. Формат Markdown совместим между приложениями, интерфейсы выбора различаются. У Ctrl-8 контекстом служит текущий открытый файл; поиск по другим файлам при выборе родителя не выполняется. Проверка циклов в JS охватывает известные связи текущего файла, без обхода хранилища.
