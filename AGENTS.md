# ObsNotes

- Работайте в этом репозитории. Пользовательские заметки и скрипты хранилища не являются исходниками приложения; не включайте их в коммиты или тестовые фикстуры.
- Не создавайте новые дневниковые файлы. Редактируйте и переносите блоки только в существующие дни. Шаблон — источник структуры, не генератор файлов.
- Сохраняйте совместимость с `Скрипты/QuickAdd/placeTimestamp.js`, `moveToHeading.js`, `createDiaryEvent.js`, `Скрипты/Modules/Дневник/crossPeopleUtils.js` и шаблоном дневника.

## Интерфейс

- Минимум переходов, нажатий и подтверждений. Прямые действия и компактные панели.
- Не выделяйте новую строку под действие, которое помещается в существующую. Второстепенные сведения раскрываются по запросу.
- У MaterialSwitch с отдельной подписью задавайте setShowText(false), textOn="" и textOff="": иначе тема Android может передать null в StaticLayout при открытии настроек.
- Все символы на кнопках — векторные, по центру, с доступным описанием и областью нажатия от 48 dp.
- Палитра Things согласована с ObsFit. Горизонтальные группы создавайте через `Ui.row()`: 8 dp между видимыми элементами, без дополнительных соседних отступов.
- Поля создавайте через `Ui.field()` с outlined-рамкой и симметричными внутренними отступами. Учитывайте системные панели, клавиатуру и поворот экрана.
- Между строками кнопок раскрытия на главном экране сохраняйте 8 dp вертикального отступа, в том числе внутри раскрытого раздела.
- Видимость разделов — локальные настройки отдельно для vault в SectionVisibilityPrefs. По умолчанию скрыты «План на день», «Важные и/или срочные задачи», «Сделано сегодня (или отмечено сделанным сегодня)». HiddenSections использует общий DayOutline.orderedSections: скрытый родитель скрывает потомков, скрытые строки исключаются до поиска/счётчиков и всех меню разделов/построчных меток. Настройки предлагают полный список и скрытые первыми, изменения применяются сразу; возвращение вложенного раздела открывает его скрытых родителей. Сохраняйте неизвестные сохранённые заголовки для восстановления и явно пустой набор после «показать всё». Не меняйте Markdown, теги, существующие назначения или полный Routing.Catalog из-за фильтра отображения; начальные выборы редактора сохраняются, даже если скрыты в меню.
- Вложенные разделы главного экрана показывайте только при раскрытии родителя, без горизонтального отступа; поиск и выбор всегда используют полный список.
- На главном экране поиск использует только видимые названия разделов (включая вложенные), имена Dataview-ключей и чистый текст существующих dairy/diary-задач с дополнениями; скрытые crossPeople-идентификаторы не участвуют; заранее построенную структуру не пересчитывайте на каждый символ. В выборе разделов сразу фокусируйте поиск и открывайте клавиатуру. Главный поиск по имени ключа показывает актуальный `Ключ:: значение`, но значение не участвует в матчинге. Обычные текстовые блоки также не участвуют в матчинге. В меню выбора раздела остаётся поиск по имени/значению поля; шаблон даёт только имена, не значения. Не индексируйте code/frontmatter, служебные теги, сгенерированные callout/скрипты или ciphertext; сохраняйте реальные блоки/смещения и приоритет точное → буквальное → нечёткое.
- Главный поиск использует заранее построенный `DaySearch`. Если видимое название раздела матчится точно, буквально или нечётко, сохраняйте всё видимое содержимое раздела и его потомков, включая обычные записи, проекции, поля/задачи и чеклист. При матчинге только содержимого возвращайте поля с подходящими именами ключей и подходящие задачи с исходными смещениями и цепочки родителей; прочие строки, блоки и подразделы скрывайте. `DaySearch.Result.fullHeadings` явно отличает целую ветку от отфильтрованной: не фильтруйте её снова в UI по запросу. Автоматически раскрывайте найденные ветки, сохраняйте ранжирование точное → буквальное → нечёткое. Не индексируйте текст обычных блоков и значения Dataview, включая проекции; содержимое целиком показывается только вследствие матчинга названия раздела. `Catalog.matchingFields(Section, query)` для главного экрана ранжирует по имени ключа, не по значению. Кнопка очистки главного поиска стирает запрос и весь expanded, включая раскрытые текстовые блоки; простое редактирование запроса не меняет сохранённое состояние раскрытия.
- После отметки задачи, удаления и фонового обновления сохраняйте прокрутку главного экрана; не фокусируйте поиск автоматически. Переход из чеклиста разрешает реальный уровень заголовка, раскрывает родителей и прокручивает после раскладки. Время загрузки чеклиста не должно временно схлопывать уже показанную таблицу.
- Правила отображения `DayContentRules` читают `excludeLines`/`excludeContains` из `diaryCleanUtils.js` без исполнения JS и копии списков. Пустые дневниковые задачи/ключи показывайте, но не считайте; значения Dataview, начинающиеся после пробелов с «Заполни», пусты для любых ключей, включая ShortDescr/ShortDescrWeek. Сами подсказки не удаляются и остаются редактируемыми; сохраняйте исключения исходных JS-предикатов. Счётчики относятся к содержательным блокам и проекциям с учётом потомков, одинаковы при поиске. Представление хранит оригинал и смещения строк: скрытые подсказки не удаляются из Markdown, дублирующиеся задачи переключаются по исходным позициям.
- Удаление текстового блока — левый свайп и подтверждение; вертикальный скролл, короткий/правый/отменённый жест не удаляют. У перекрёстного отображения удаляется оригинал, у корня подтверждение объясняет потерю связей.
- Поисковые поля главного экрана и выбора имеют справа в той же строке центрированную векторную кнопку очистки 48 dp, с отступом 8 dp. Очистка запроса не сбрасывает выбранные назначения.
- `#task/diary` и `#task/dairy` с вложенными тегами, а также обычные задачи без тега `#task` рендерятся чекбоксами через общий DiaryTasks.isSupported. Чужие категории `#task/...` сохраняют прежнее поведение. Задачи без тега доступны также в поиске и редакторе значений; не добавляйте им служебный тег при сохранении. DayContentRules.excluded отражает исходные списки очистки JS, hidden отдельно оставляет поддерживаемые задачи видимыми; неотмеченные не увеличивают счётчики, даже если стоят в excludeLines. Правила очистки Obsidian не меняйте из-за отображения в Android. Только квадрат слева переключает отметку. Нажатие текста открывает `EditorState.editTask`: `TaskValue` отделяет защищённое название/состояние от сохранённого значения после `;`; `taskShell` сериализуется в recovery, якорь остаётся общей метаинформацией части. Значение можно заменить и очистить; непустая запись отмечает задачу, очистка сохраняет её текущее состояние. Строки соединяются через `; `; пустая строка создаёт независимую часть. Сохраняйте исходные смещения отдельных задач внутри общего блока, соседние строки, CRLF и позицию возврата. Дата выполнения из заметки; при снятии отметки она удаляется. Старый taskAppend поддерживается для совместимости recovery, новые формы его не используют.
- Режим переноса в задачу — кнопка с явными состояниями «С текстом» / «Без текста», без галочки; переключение сохраняет прежнюю семантику appendTaskText и recovery.
- «Чеклист» — нативная таблица по `dairyCheckList`: заполнение любого «Перекус 1»…«Перекус 4» делает «Перекусы» зелёными; пустые/соседние заголовки не заполняют пункт. JS и native проверяются общими вымышленными примерами. Обе ячейки каждой строки таблицы имеют общую высоту и верхнее выравнивание текста, в том числе при переносах длинных значений; навигация по ячейкам сохраняется. Вспомогательные файлы читаются только по точным путям при раскрытии. Погодная форма редактирует значения двух ключей и дописывает nuipogoda по дате назначения без перезаписи введённого. Запросы погоды выполняются отдельно от файловой очереди и отменяются при выходе; сеть не получает содержимое заметок.
- Дни открывайте по вычисленному пути без обхода папок. Список переноса начинает с двух дней вперёд от исходного файла и загружает по 14 дат назад с `ShortDescr`; только существующие файлы. Календарь позволяет выбрать другую дату, включая будущую, с той же проверкой существования. RelativeDates показывает «Вчера», «Позавчера», «Завтра», «Послезавтра» относительно исходного файла, независимо от часов и уже выбранного назначения.
- Тап по дате главного экрана открывает DayCalendarDialog: существующая дата красная, если CalendarDays находит содержимое в «## Заметки»/потомках по DayContentRules или отсутствует содержательный ShortDescr; подсказки «Заполни» пусты. Остальные существующие даты белые, отсутствующие/ещё не проверенные тёмные и недоступны. Правила скрытия разделов не меняют фактическое состояние дня. Год/месяц быстро выбираются тапом по заголовку календаря. Загружайте только показанный месяц по DiaryLayout: метаданные всех дат, содержимое только существующих; без обхода архива и исполнения JS. Кэш статусов живёт только в диалоге, при смене месяца/закрытии отменяйте работу и отклоняйте устаревшие callbacks. Не держите файловую очередь и основной UI занятыми. Выбор даты всё равно проходит свежую проверку DayNavigation, удалённый файл не меняет текущую заметку.
- Правая стрелка главного экрана тёмно-серая (Ui.DISABLED) и отключена, пока наличие следующего календарного дня не подтверждено. SafVaultStorage.exists запрашивает только метаданные по вычисленному URI, без чтения файла или обхода архива. Проверка идёт в отдельной фоновой очереди; NextDayAvailability кэширует результат 5 секунд, объединяет ожидающие проверки и отклоняет устаревшие ответы после смены дня/vault. Обновляйте только кнопку, сохраняя прокрутку/фокус; общий busy не должен включать недоступную стрелку. Будущие существующие файлы остаются доступны.
- Отсутствующий день не меняет текущую дату, документ или редактор и не блокирует управление. Ошибка — «Заметка не найдена», красная. Возврат к сегодняшнему дню доступен одним нажатием; между датой и разделами 8 dp. «Сегодня» находится в верхней панели главного экрана; в редакторах этой кнопки нет; внутри серых карточек сверху и снизу 8 dp.
- Кнопка `+` в заголовке каждого раздела создаёт запись сразу в этом разделе, включая вложенные и результаты поиска. Не добавляйте для неё отдельную строку. Редактор открывается с фокусом текста и клавиатурой; существующий блок начинает с конца чистого текста, возврат из выбора сохраняет позицию. Курсор в Dataview-полях относится к значениям, не к именам ключей или служебным тегам.
- «На строку» использует тот же канонический буквенный crossPeople-идентификатор на раздел, что и Routing.Catalog; не удаляйте разделы из списка по общим алиасам. Поиск учитывает все алиасы, существующие метки сохраняют исходный алиас при перевыборе; person/personOneLine остаются ограничены поддерживаемыми именами.
- Для каждой части редактор имеет упорядоченный выбор «Разделы»: первый пункт — физическое назначение (белая метка), следующие — crossPeople (фиолетовые). Удаление первого продвигает следующий. Галочки сохраняют порядок нажатий, нажатие на название применяет выбор и закрывает меню; подтверждение находится сверху.
- Дополнения к задачам и обычные Dataview-значения используют общий EditorPartsScreen с многострочным вводом. Пустая строка создаёт независимую часть в «Заметки» со своими назначениями/метками/связями. Для существующих полей fieldPrefix хранит защищённое имя отдельно от редактируемого текста; метка `Ключ::` показывает тип, значок квадрата с галочкой и название задачи — тип задачи. Тап по любой метке значения позволяет сменить назначение (включая другой ключ/задачу), корзина снимает оболочку и оставляет обычный текст в разделе; сохраняйте якорь. После удаления всех меток разделов назначение значения тоже должно заменяться без ошибки; исходные ключи (включая пустые) не теряются при разделении, очистке и восстановлении. Несколько исходных ключей имеют отдельные части, при обычной записи сохраняются соседними строками. Значение задачи соединяет строки при сохранении; очистка убирает прежнее значение, сохраняя название и состояние задачи; дополнительные части сохраняются независимо. v4 EditorRevision мигрирует исходный baseline, recovery хранит fieldPrefix. Погода через отдельную форму сохраняет свои поля и добавление nuipogoda.
- Обычный редактор остаётся одним полем: пустые строки вне fenced-кода разделяют его на произвольное число частей. Все панели частей видны одновременно и содержат только метки, без номера и текста части. Общая широкая кнопка даты действует на все части; ниже общий ряд «Разделы», «На строку» и человек, действующий по курсору. Нажатие метки меняет именно её часть независимо от курсора. Карточка каждой части остаётся видимой даже без меток (минимальная высота 48 dp); не скрывайте пустую карточку вслед за ChipGroup. Всегда выделяйте карточку под курсором тонкой белой рамкой, в том числе единственную, без смены фокуса и прокрутки; обновляйте её по событиям выделения, не только при вводе. Сохраняйте назначения, построчные метки и идентичность частей при вставке/удалении. Несовместимое объединение не теряет назначений и связей. Галочки связей нет: общая кнопка «Связать» действует на часть под курсором и открывает выбор внутреннего или внешнего корня; пустые метки «Связь» не показывайте; каждое нажатие «Связать» добавляет ещё одного родителя; тап по метке заменяет только эту связь, её корзина удаляет только её. Все родители показаны отдельными метками; допускаются цепочки и несколько родителей одновременно. Корзина корня убирает его якорь/callout и ведущие ссылки на него в текущем файле, сохраняя другие связи, обычные ссылки и другие дни. Сам корень может иметь родителей. PartLinks хранит идентификаторы, а не индексы, отклоняет циклы до изменения состояния и сохраняется в EditorRecovery. Промежуточный корень имеет и ведущую wiki-ссылку, и собственный якорь/callout; таймстамп не может предшествовать ведущей ссылке. Сохраняйте существующие якоря, исходные байты и единый журнал, назначение записывается до удаления исходника.
- Нажатие на выбранную метку открывает адресную замену с текущим выбором. Основной и дополнительные разделы сохраняют позиции; построчные метки — исходную строку и вид. Быстрый выбор имени заменяет метку, галочки позволяют изменить набор. Нажатие на метку корня открывает просмотр связей; корзина снимает корневую роль.
- Сортируйте меню назначения/допсвязей по суммарной частоте сохранённых назначений `SectionUsage`, оставляя весь доступный список. Учитывайте только успешный commit, новые назначения и связи; обычную правку, пустые записи, отмены, удаление и ошибку сохранения не считайте. Поиск сохраняет приоритет точное → буквальное → нечёткое; частота действует внутри групп и не меняет порядок галочек. `UsageHistory` хранит только счётчики отдельно для каждого vault URI, без записи в заметки и обхода архива.
- Все поисковые поля используют общий `FuzzySearch` с порядком полное совпадение → буквальное вхождение → нечёткое совпадение и стабильным порядком внутри групп: буквы с пропусками в исходном порядке, без учёта регистра. В меню выбора разделов/тегов поиск также учитывает crossPeople-идентификаторы; главный поиск использует только видимые названия разделов. Строки поисковой подписи — независимые поля: нечёткое совпадение не пересекает границу между названием, его повтором, значением и алиасом. Пробелы запроса игнорируются, буквы могут идти с пропусками внутри одного поля.
- Перенос в Dataview-ключ дописывает часть через `; `; многострочная часть перед записью также соединяется через `; `. Существующие Dataview-ключи защищены: редактируются отдельные значения. Задачу можно отметить без переноса текста; выбор этого режима должен сохраняться при восстановлении редактора.
- Приложение работает только в портретной ориентации.
- Назад и уход в фон сохраняют редактор без подтверждения только при содержательных изменениях. EditorRevision сравнивает итоговые текст, части, назначения, теги и связи с исходным снимком: курсор и состояние выбора не считаются правками, ручной возврат к исходному состоянию не запускает I/O хранилища, сжатие, журнал и историю частот. Снимок сохраняется в EditorRecovery; старые снимки восстанавливают исходное состояние из sourceSnapshot, а не текущих правок. Пустая новая форма остаётся без записи, но явная отметка задачи без текста — изменение. Отдельной работы с черновиками в интерфейсе нет. Пустая новая запись — без изменений, очищенная существующая — удаление исходного блока с защитой якорей. Внутренний снимок восстанавливает текст после ошибки или прерывания; очищайте его после проверенного commit, даже если Activity уже уничтожена.
- При конфликте сохранения дайте явный выбор: копия видимого текста в «Заметки» исходного дня, отмена своей правки с открытием свежего файла или продолжение редактирования. Копия не удаляет оригиналы, не дублирует якоря, callout, активные Dataview-ключи и служебные метки; внешние правки не перезаписываются. Выбор принимает частичную транзакцию как есть с сохранением резервных версий. Конфликт восстановления журнала не должен закрывать доступ к редактору и разрешению конфликта.
- Поле текста не содержит служебных crossPeople/person/oneLine-тегов, callout, якорей и всех ведущих ссылок на корни. Метаданные сохраняйте через состояние редактора и показывайте под полем.
- Индексы цветов строк общие для всех частей редактора, палитра LineColors не повторяется после шести цветов. Цвет шрифта строк и совпадающий цвет меток используйте только для crossOneLine/personOneLine, без надписей с номером строки. Фон поля не окрашивайте. crossPeople/person для всего блока не подсвечивают текст; их метки идут первыми, фиолетовые, без слова «блок».

- Выбор события для связи использует текущие DayContentRules: блоки только из скрытых строк не предлагайте, в смешанных блоках скрывайте подсказки в подписи и поиске. Якоря, callout и ссылки не делают скрытый блок видимым; сохраняйте оригинальный Markdown.Block и его смещения для проверок конфликтов и записи.

- Ведущие wiki-ссылки на родителей не исключают блок из кандидатов на корень: он может стать промежуточным звеном цепочки. При выборе создавайте его собственный якорь/callout, сохраняя все прежние родительские ссылки, теги и исходные смещения. Не используйте наличие `#^` в тексте как фильтр кандидатов.

- В общем списке событий для связи сначала показывайте существующие корни (якорь вместе с callout outLinkInfo), затем кандидатов; внутри групп сохраняйте порядок заметки. Поиск сохраняет общий приоритет точное → буквальное → нечёткое, порядок групп действует внутри одинаковой релевантности.

- Список внешних корней читает только destinationPath выбранной даты, без обхода архива. Исключайте исходный блок по смещению только если sourcePath == destinationPath; одинаковые смещения в других днях не относятся к редактируемому блоку. DiaryIndex проверяет актуальность выбранного файла/блока перед добавлением связи, внешние изменения не затираются.

- Цепочка без ведущей ссылки и без якоря с callout не должна читать или перечислять файлы. Корень по ссылке открывается по точному пути. Поиск входящих связей отменяется при закрытии окна и не блокирует редактор или сохранение; результаты показываются по мере чтения.

- Шифрование совместимо с локальным inline-encrypter CryptoFactory: AES-256-GCM, IV 16 байт, соль 16 байт, PBKDF2-HMAC-SHA512/262144, tag 128 бит; Base64(IV || salt || ciphertext+tag) в одиночных backticks `secret …`. Используйте Bouncy Castle GCM для 16-байтового IV: Android Conscrypt принимает только 12. Не меняйте провайдеры JCA глобально и не пишите собственные криптопримитивы.
- Замок расположен в общем ряду «Разделы / На строку / человек» и действует на часть под курсором. Закрытые secret показаны защищёнными плейсхолдерами; payload не попадает в поле и clipboard. Частичная правка плейсхолдера запрещена, целое удаление явно удаляет содержимое. Пустые строки делят расшифрованный текст на части точно как обычный текст; замок шифрует только часть под курсором. Содержащиеся в plaintext ключи, якоря и wiki-ссылки не становятся служебными метаданными редактора. Внутренняя opened-оболочка не является форматом хранилища и никогда не должна попадать в Markdown.
- Только выход из редактора сохраняет положение замка: закрыт → secret, открыт → обычный текст. Чтение и повторное закрытие одного текстового блока без правок восстанавливает исходный ciphertext и не пишет файл. Уход в фон секретного редактора сохраняет только защищённый recovery, не Markdown. Сравнение EditorRevision учитывает ciphertext, а не только одинаковые плейсхолдеры.
- Пароль задаётся отдельно для каждого vault в настройках, хранится только в PIN-зашифрованном виде; PIN — ровно четыре ASCII-цифры. Новые пароль/PIN вводятся дважды, оба новых поля видимы; несовпадение не меняет настройку и показывается только красным векторным значком в поле, без текстовых подсказок. Старый PIN и PIN разблокировки остаются скрытыми. Смена PIN, пароля и удаление требуют старый PIN, даже при активном кэше. Смена пароля не перешифровывает архив. Операции доступны только после создания пароля. Кэш char[] очищается через 180000 мс от успешного PIN по монотонным часам, без продления при использовании, при смене vault и уничтожении Activity; копии для фоновых операций стираются в finally. PIN и пароль не сериализуются открытыми. Для таких полей отключайте autofill и персональное обучение IME.
- Recovery секретного контекста запечатывается ключом Android Keystore; открытые текст, пароль и PIN не должны оставаться в JSON SharedPreferences или Bundle. Шифрование заметок и PBKDF2 выполняйте вне UI-потока. Проверки используют только синтетические пароли/данные; реальный secret из дневника можно читать структурно, не расшифровывайте его без отдельной необходимости.

- Рабочий спутник дневника — только точный `WorkDaily.path(date)` внутри `Работа/Daily/Хроника`, с суффиксом `-work.md`; тот же путь использует чеклист. Не сканируйте архив и не создавайте рабочие файлы. При наличии файла показывайте после «Новости» синтетическую ветку «Работа → Основные события»; показывайте/редактируйте только реальные блоки из `## Основные события`, сохраняя их путь и исходные смещения. Остальные рабочие разделы не импортируйте. WorkDaily.ROUTE — назначение редактора, а не заголовок для записи: нормализация в core направляет его в рабочий файл; канонический destinationPath редактора остаётся дневниковым контекстом выбранной даты. workSnapshot — отдельный снимок рабочего назначения, включая recovery; проверяйте его при commit. Рабочая часть не имеет допразделов/crossPeople/построчных меток и внутренних связей; при смене даты проверяйте существование рабочего файла до изменения формы. Рабочее назначение доступно по слову «Работа» и подчиняется настройкам скрытия разделов. Все назначения нескольких частей запишите и проверьте до удаления из исходного файла. При конфликте рабочей записи копия идёт в «Заметки» дневникового файла исходного дня. Сгенерированный callout `> [!info]- Работа за YYYY-MM-DD` скрывайте целиком через DayContentRules, сохраняя исходный Markdown и смещения окружающего текста.

- Свайп вправо выбирает/снимает выбор обычного текстового блока; долгое нажатие для выбора не используется. BlockSelection хранит физический оригинал с путём, смещениями и снимком: проекция crossPeople выбирает тот же оригинал один раз. Поиск/раскрытие не меняют выбор. В верхней панели сохраняется ObsNotes; вместо трёх обычных действий справа две квадратные кнопки 48 dp: число открывает общий редактор всех выбранных (включая скрытые поиском), центрированный векторный крестик снимает выбор без удаления. В режиме выбора тап по обычной записи или её стрелке переключает выделение; снятие последнего возвращает обычный режим. SelectionControls меняет действия панели и рамки на месте, без пересоздания экрана/каталога/поискового индекса. Задачи и поля остаются отдельными редакторами.
- EditorBatch хранит исходные непересекающиеся диапазоны и снимки нескольких записей, использует обычные EditorParts, их теги/связи и общий VaultRepository. Origins переживают split/merge и Recovery, незатронутые записи остаются на прежних местах. Очистка поля с последующим вводом сохраняет исходные назначения; состояние без изменений не пишет файлы. Сохраняйте исходные байты при правке на месте, сжатие запускайте при переносе/разделении/объединении/удалении. Межфайловые назначения записываются раньше удаления оригиналов; встречные циклические переносы отклоняйте до записи. Recovery с чувствительным исходником любого выбранного файла шифруется целиком.
- Объединение корня с ссылающейся на него частью в любом порядке убирает ставшую внутренней ссылку и сохраняет исходный якорь/callout, дополнительных родителей и входящие ссылки третьих блоков. Два разных существующих якоря не теряйте: сохраняйте редактируемое состояние с ошибкой до явного снятия лишней корневой роли. Не допускайте новых циклов при объединении графа.
- Долгое нажатие на физический текстовый блок начинает drag-and-drop, только внутри того же файла и того же реального Markdown.Section. Проекции не перемещаются и не принимают drop; фактическая перестановка — BlockOrder, без изменения заголовков, промежутков/таймстампов и служебных скриптов. Горизонтальный свайп отменяет pending long press. У перетаскивания есть автопрокрутка, сохранение позиции и проверка исходной версии перед записью.

- Разделы не имеют накопительного горизонтального отступа. Внутри каждого сохраняйте стандартные 10 dp по бокам для заголовка с кнопками, «Пусто», полей и чеклиста; у карточек записей также 10 dp по бокам и 8 dp сверху/снизу. Не обнуляйте отступы видимого содержимого ради выравнивания подразделов.
- Не компилируйте регулярные выражения внутри построчного разбора Markdown и не проходите весь документ заново для каждого раздела. Каталог редактора кешируется только по снимкам назначения/шаблона и наличию рабочего файла; инвалидацию проверяйте тестами. Перемещение курсора меняет рамки/значки только при смене состояния. EditorPanels сравнивает видимые метаданные: обычный ввод не пересоздаёт карточки/метки, их callbacks получают актуальную форму через supplier; EditorParts копирует формы при вводе. Снятие обычного назначения обновляет панели локально. Парсинг фоновых обновлений оставляйте в I/O-очереди. Keystore recovery переиспользует системный дескриптор ключа, не пароль/PIN.

## Архитектура и проверки

- Проверки на устройстве выполняйте только по отдельной просьбе пользователя. По умолчанию используйте автоматические тесты, сборку и lint; наличие подключённого телефона само по себе не означает запрос на проверку.

- Логика Markdown, формы, переходы формы, связи, план сохранения и проверки конфликтов находятся в `core`, без Android-зависимостей.
- Экраны и общие виджеты находятся в `app/.../ui`; данные формы хранятся в `EditorState`, не в Android-полях.
- Документы Android обслуживает `SafVaultStorage`, реализующий `VaultStorage`. Все операции с хранилищем выполняйте в фоне.
- Обычное редактирование сохраняет исходные байты вне изменяемых диапазонов и исходный LF/CRLF. После переноса очищайте изменённые файлы: последовательные пустые строки, осиротевшие таймстампы и пустые словесные маркеры по Ctrl+`. Защищайте frontmatter, код и callout. Неизменённые файлы не сжимайте.
- Список пустых маркеров принадлежит хранилищу: `CleanupRules.PATH`, раздел `## Пустые маркеры`. Не дублируйте его в исходниках. Читайте настройки в фоне перед сжатием по точному пути; при отсутствии файла сохраняйте слова, при ошибке чтения/формата не записывайте заметки. JS Ctrl+` использует тот же файл; изменения самого JS и настроек вносятся в хранилище, не копируйте пользовательские скрипты в репозиторий приложения.
- После каждой законченной доработки оцените дублирование, границы core/ui и согласованность предпросмотра с сохранением. Выполните необходимый рефакторинг в рамках задачи.
- Покрывайте новое поведение содержательными тестами сценариев и границ данных. Особое внимание: исходник не удаляется до проверенной записи назначения, внешние изменения не затираются, прерванные операции восстанавливаются без повторной вставки.
- Для промежуточной проверки: `./gradlew :core:test :app:lintDebug`. При изменении релизного скрипта: `python3 -B -m unittest discover -s tools -p 'test_*.py'`.
- После каждой законченной доработки, включая документацию, увеличивайте `versionCode` и `versionName`, затем запускайте `python3 tools/release.py`. Один выпуск после финальных правок задачи. Скрипт оставляет три последние APK в `dist/`.

## GitHub

- После успешных проверок и выпуска создайте коммит и выполните обычный `git push` в `https://github.com/delorum/ObsNotes` без force.
- Коммит описывает проблему, поведение, выполненные проверки и ограничения. Для многострочного сообщения используйте `git commit -F`.
- Включайте только исходники и документы текущей задачи. Не коммитьте APK, `dist`, локальные настройки, ключи, пользовательские заметки, журналы или черновики.
- В финальном ответе дайте ссылку на собранный APK и сообщите, если тесты, сборка, lint или push не прошли. Не объявляйте проверку на устройстве выполненной без реального запуска.

- Совместимость Ctrl-8/outLinkInfo с Java проверяйте через `tools/CheckDiaryEvents.java` и тест `Скрипты/Tests/diaryEvents.test.cjs` в хранилище (только синтетические данные). Не копируйте скрипты/заметки в репозиторий приложения. Инструкции и границы сценариев — `docs/diary-events.md`.
