# ObsNotes

- Работайте в этом репозитории. Пользовательские заметки и скрипты хранилища не являются исходниками приложения; не включайте их в коммиты или тестовые фикстуры.
- Не создавайте новые дневниковые файлы. Редактируйте и переносите блоки только в существующие дни. Шаблон — источник структуры, не генератор файлов.
- Сохраняйте совместимость с `Скрипты/QuickAdd/placeTimestamp.js`, `moveToHeading.js`, `createDiaryEvent.js`, `Скрипты/Modules/Дневник/crossPeopleUtils.js` и шаблоном дневника.

## Интерфейс

- Минимум переходов, нажатий и подтверждений. Прямые действия и компактные панели.
- Не выделяйте новую строку под действие, которое помещается в существующую. Второстепенные сведения раскрываются по запросу.
- Все символы на кнопках — векторные, по центру, с доступным описанием и областью нажатия от 48 dp.
- Палитра Things согласована с ObsFit. Горизонтальные группы создавайте через `Ui.row()`: 8 dp между видимыми элементами, без дополнительных соседних отступов.
- Поля создавайте через `Ui.field()` с outlined-рамкой и симметричными внутренними отступами. Учитывайте системные панели, клавиатуру и поворот экрана.
- Между строками кнопок раскрытия на главном экране сохраняйте 8 dp вертикального отступа, в том числе внутри раскрытого раздела.
- Вложенные разделы главного экрана показывайте только при раскрытии родителя; поиск и выбор всегда используют полный список.
- Дни открывайте по вычисленному пути без обхода папок. Список переноса загружает по 14 дат назад и показывает `ShortDescr`.
- Отсутствующий день не меняет текущую дату, документ или редактор и не блокирует управление. Ошибка — «Заметка не найдена», красная. Возврат к сегодняшнему дню доступен одним нажатием; между датой и разделами 8 dp. «Сегодня» находится в верхней панели; внутри серых карточек сверху и снизу 8 dp.
- Редактор имеет один упорядоченный выбор «Разделы»: первый пункт — физическое назначение (белая метка), следующие — crossPeople (фиолетовые). Удаление первого продвигает следующий. Галочки сохраняют порядок нажатий, нажатие на название применяет выбор и закрывает меню; подтверждение находится сверху.
- Все поисковые поля используют общий `FuzzySearch`: буквы с пропусками в исходном порядке, без учёта регистра. Разделы ищутся также по всем идентификаторам crossPeople из шаблона.
- Перенос в Dataview-ключ доступен только для однострочного текста и дописывает его через `; `. Существующие Dataview-ключи защищены: редактируются отдельные значения. Задачу можно отметить без переноса текста; выбор этого режима должен сохраняться при восстановлении редактора.
- Приложение работает только в портретной ориентации.
- Назад, «Сегодня» и уход в фон сохраняют редактор без подтверждения. Отдельной работы с черновиками в интерфейсе нет. Пустая новая запись — без изменений, очищенная существующая — удаление исходного блока с защитой якорей. Внутренний снимок восстанавливает текст после ошибки или прерывания; очищайте его после проверенного commit, даже если Activity уже уничтожена.
- Поле текста не содержит служебных crossPeople/person/oneLine-тегов, callout, якорей и ведущей ссылки на корень. Метаданные сохраняйте через состояние редактора и показывайте под полем.
- Цвет шрифта строк и совпадающий цвет меток используйте только для crossOneLine/personOneLine, без надписей с номером строки. Фон поля не окрашивайте. crossPeople/person для всего блока не подсвечивают текст; их метки идут первыми, фиолетовые, без слова «блок».

- Цепочка без ведущей ссылки и без якоря с callout не должна читать или перечислять файлы. Корень по ссылке открывается по точному пути. Поиск входящих связей отменяется при закрытии окна и не блокирует редактор или сохранение; результаты показываются по мере чтения.

## Архитектура и проверки

- Логика Markdown, формы, переходы формы, связи, план сохранения и проверки конфликтов находятся в `core`, без Android-зависимостей.
- Экраны и общие виджеты находятся в `app/.../ui`; данные формы хранятся в `EditorState`, не в Android-полях.
- Документы Android обслуживает `SafVaultStorage`, реализующий `VaultStorage`. Все операции с хранилищем выполняйте в фоне.
- Обычное редактирование сохраняет исходные байты вне изменяемых диапазонов и исходный LF/CRLF. После переноса очищайте изменённые файлы: последовательные пустые строки, осиротевшие таймстампы и пустые словесные маркеры по Ctrl+`. Защищайте frontmatter, код и callout. Неизменённые файлы не сжимайте.
- После каждой законченной доработки оцените дублирование, границы core/ui и согласованность предпросмотра с сохранением. Выполните необходимый рефакторинг в рамках задачи.
- Покрывайте новое поведение содержательными тестами сценариев и границ данных. Особое внимание: исходник не удаляется до проверенной записи назначения, внешние изменения не затираются, прерванные операции восстанавливаются без повторной вставки.
- Для промежуточной проверки: `./gradlew :core:test :app:lintDebug`. При изменении релизного скрипта: `python3 -B -m unittest discover -s tools -p 'test_*.py'`.
- После каждой законченной доработки, включая документацию, увеличивайте `versionCode` и `versionName`, затем запускайте `python3 tools/release.py`. Один выпуск после финальных правок задачи. Скрипт оставляет три последние APK в `dist/`.

## GitHub

- После успешных проверок и выпуска создайте коммит и выполните обычный `git push` в `https://github.com/delorum/ObsNotes` без force.
- Коммит описывает проблему, поведение, выполненные проверки и ограничения. Для многострочного сообщения используйте `git commit -F`.
- Включайте только исходники и документы текущей задачи. Не коммитьте APK, `dist`, локальные настройки, ключи, пользовательские заметки, журналы или черновики.
- В финальном ответе дайте ссылку на собранный APK и сообщите, если тесты, сборка, lint или push не прошли. Не объявляйте проверку на устройстве выполненной без реального запуска.
