# ObsNotes

Личный Android-клиент для ежедневных заметок Obsidian. Android 13 и новее. Тёмная палитра Things и компактные элементы интерфейса по образцу ObsFit. Приложение работает непосредственно с Markdown в выбранной папке; Syncthing синхронизирует её независимо от приложения.

## Установка и работа

1. Установите APK из `dist/` и выберите **корневую папку хранилища** через системный диалог Android. Подтвердите доступ на чтение и запись. В папке должны находиться `Дневник/Хроника` и `Шаблоны/Шаблон дневниковой записи.md`.
2. Дата открывает календарь; стрелки переключают дни. Под датой есть поиск по видимым названиям разделов, именам Dataview-ключей и тексту существующих задач `#task/dairy`/`#task/diary`, включая их дополнения и вложенные разделы. Если видимое название раздела матчится с запросом (точно, буквально или нечётко), поиск раскрывает раздел и показывает всё его содержимое, включая обычные записи и подразделы. Если матчится имя Dataview-ключа или текст задачи, раскрывается путь до результата, а прочие записи и подразделы скрываются. Значения Dataview и текст обычных блоков в главном поиске не участвуют; при матчинге названия раздела его содержимое по-прежнему видно целиком. Скрытые идентификаторы разделов в главном поиске не участвуют; в меню выбора разделов/тегов они остаются доступны. Справа от поля есть кнопка очистки; она стирает запрос и схлопывает все разделы и записи. Например, «Температура» находит раздел «Погода», а в результате видно имя ключа вместе с его текущим значением. Совпавшие `Ключ:: значение` видны прямо под заголовком в результатах поиска; тап открывает их редактирование. Имена и значения доступны также в выборе раздела, с тем же нечётким поиском. Название, значение и алиасы проверяются независимо: буквы нечёткого запроса должны найтись внутри одного поискового поля, без перехода в другое поле или повтор названия. Кнопка календаря «Сегодня» в верхней панели рядом с настройками возвращает к сегодняшнему дню одним нажатием. На экране редактирования кнопки «Сегодня» нет. Переход к отсутствующему дню оставляет текущую дату, документ и редактор, показывает красное «Заметка не найдена» и сохраняет отзывчивость кнопок. **Приложение не создаёт дневниковых файлов и не исполняет Templater.**
3. Кнопка `+` в строке любого раздела открывает редактор с этим основным разделом; для вложенных разделов она доступна после раскрытия родителя и в результатах поиска. Курсор сразу стоит в поле текста, клавиатура открывается автоматически. При редактировании существующего блока курсор начинается в конце видимого текста; при возврате из выбора разделов сохраняется текущая позиция. Главный экран показывает верхние разделы; подразделы появляются только внутри раскрытого родителя. Счётчик родителя включает вложенные блоки и перекрёстные отображения. Стрелки раскрывают раздел и текст блока. Нажатие на текст открывает редактирование оригинала, включая блоки, показанные через crossPeople. Свайп влево предлагает удалить запись с подтверждением; отмена ничего не меняет. Для перекрёстного отображения удаляется его оригинал. Если удаляется корневой блок, подтверждение сообщает о связях.
4. «Разделы» открывает общий список назначения: первый выбранный пункт получает текст, последующие разделы добавляются в `crossPeople`. Галочки запоминают порядок нажатий; удаление первого пункта продвигает следующий. Основная метка белая, дополнительные — фиолетовые. Нажатие на название выбирает и сразу закрывает меню; галочки позволяют набрать несколько пунктов, подтверждение находится сверху. Все подразделы доступны всегда. Кнопка очистки справа от поиска стирает запрос, сохраняя порядок галочек. Задачи и Dataview-поля существующего дня можно выбрать первыми. Поиск получает фокус и открывает клавиатуру сразу после открытия выбора. Однострочный текст дописывается в задачу или значение поля через `; `. Строки одной части при записи в Dataview-ключ или задачу соединяются через `; `. У выбранной задачи кнопка переключается между «С текстом» и «Без текста»: во втором режиме сохранятся только отметка выполнения и дата, исходный переносимый текст уберётся из прежнего места. Ключи существующих Dataview-полей показаны в метках отдельных полей ввода; редактируются только значения.
5. Кнопка даты в редакторе открывает список **существующих дней** от двух дней вперёд относительно исходной заметки назад. Строка содержит дату и значение `ShortDescr`; соседние даты подписаны «Вчера», «Позавчера», «Завтра», «Послезавтра» относительно исходного файла. Календарь в заголовке позволяет выбрать любую другую существующую заметку, включая будущие дни. Читаются порции по 14 календарных дат, следующие подгружаются при прокрутке; отсутствующие файлы пропускаются. Если вся порция пуста, следующую можно загрузить кнопкой внизу списка. Выберите раздел назначения и нажмите векторную кнопку сохранения в верхней панели. Целевой файл записывается и проверяется до удаления исходного блока. После сохранения открывается день назначения.
6. «На строку» предлагает каждый раздел с совместимым crossPeople-идентификатором из шаблона один раз, как и «Разделы»: общий алиас у нескольких разделов не скрывает отдельный раздел с таким идентификатором. Поиск учитывает все алиасы раздела, а при изменении старой метки сохраняет её исходный идентификатор. «Разделы» и «На строку» позволяют выбрать несколько идентификаторов; теги записываются в совместимом формате `#crossPeople/ЛенаПокупки` или `#crossOneLine/Утро`. Для строки используется положение курсора. Кнопка человека добавляет `#person/` или `#personOneLine/` перед существующим именем, если оно найдено; поддерживаются Лена, Аня, Вика, Мама. Служебные теги скрыты из поля ввода; имя человека остаётся обычным текстом. Метки представлены под полем и удаляются своей векторной кнопкой. Метки всего блока идут первыми и окрашены фиолетовым, без слова «блок». Только строки с `crossOneLine` и `personOneLine` получают цвет шрифта; соответствующие метки окрашены так же, без номера строки. Фон поля не меняется. `crossPeople` и `person` для всего блока не окрашивают текст. Вставка обычных строк сохраняет привязки и цвета отмеченных строк; удаление имени снимает его метку.
7. «Сделать корневым» добавляет стабильный `^event-…` и callout `outLinkInfo`. «Связать» показывает сначала готовые корни с якорем и callout, затем обычные блоки выбранного дня назначения; внутри каждой группы сохраняется порядок заметки. Поиск сортирует совпадения по релевантности, сохраняя этот порядок при равном совпадении; плейсхолдеры из общих правил отображения не предлагаются как события и скрываются в подписях смешанных блоков. Как Ctrl-8: обычный выбранный блок становится корневым при сохранении. Кнопка цепочки проверяет ведущую wiki-ссылку либо сочетание якоря с callout `outLinkInfo`. Без этих признаков сразу показывает, что связей нет, не обращаясь к файлам. Ведущие ссылки открывают только указанные корневые файлы, каждый по точному пути и без повторного чтения. Для сохранённого корня сначала показываются дополнения текущего дня, затем подгружаются найденные дополнения из архива. Служебный callout, якорь и ведущая ссылка на корень скрыты из поля и сохраняются при редактировании. Каждая связь показана отдельной меткой под полем; все ведущие ссылки скрыты из текста.

В настройках кнопка **«Скрытые разделы»** открывает полный список с поиском по названиям и идентификаторам. Скрытые идут первыми; переключатель сразу показывает или скрывает раздел на главном экране, в поиске и выборе назначений/построчных меток. Скрытый родитель скрывает и вложенные разделы; включение вложенного возвращает необходимых родителей. По умолчанию скрыты «План на день», «Важные и/или срочные задачи» и «Сделано сегодня (или отмечено сделанным сегодня)». Выбор хранится отдельно для каждого хранилища и сохраняется после перезапуска; текст файлов и существующие связи остаются прежними.

Тап по дате главного экрана открывает календарь. Красные числа — в «Заметках» осталось содержимое или не заполнен `ShortDescr` (в том числе осталась подсказка «Заполни…»); белые — «Заметки» пусты и краткое описание заполнено. Плейсхолдеры и пустые факты учитываются по тем же правилам, что в счётчиках. Отсутствующие даты тёмные и не выбираются. Тап по названию месяца открывает быстрый выбор месяца/года, тап по существующей дате сразу открывает заметку. Состояния подгружаются в фоне только для показанного месяца и обновляются при новом открытии календаря.

Правая стрелка на главном экране тёмно-серая и неактивна, если заметки следующего календарного дня нет. Проверка идёт в фоне по точному пути: Android читает только метаданные файла, результат кэшируется на 5 секунд. Появление или удаление заметки через Syncthing обновляет только стрелку при следующей фоновой проверке.

Назад и уход из приложения сохраняют текущее содержимое без подтверждения. Отдельных черновиков и кнопок для работы с ними нет. Пустая новая запись не добавляется; очистка существующего текста удаляет его исходный блок, кроме защищённого корня с якорем. При ошибке записи текст остаётся в редакторе; прерванная запись восстанавливается при следующем запуске. Снимки для восстановления хранятся внутри приложения и не заменяют проверку внешних изменений. Приложение всегда остаётся в портретной ориентации.

Нажатие на выбранную метку открывает замену с отмеченным текущим значением. Замена основного раздела или допраздела сохраняет порядок остальных назначений. Построчная метка сохраняет исходную строку и цвет независимо от положения курсора. Нажатие на имя сразу заменяет назначение; для перекрёстной метки галочками можно изменить несколько идентификаторов и применить их сверху. Нажатие на метку корня открывает перевыбор родительского события.

Если файл изменился извне и сохранение конфликтует, появляется выбор: **«Сохранить копию»**, **«Отменить правку»** или **«Остаться»**. Копия добавляет видимый текст отдельной записью в «Заметки» исходного дня, сохраняя текущие внешние данные. В копии нет служебных тегов и связей, якорей и callout; названия редактируемых Dataview-полей остаются обычными подписями, чтобы не создать повторные активные ключи. Отмена открывает свежий файл без записи. Если конфликт возник посреди переноса, эти действия принимают уже записанные части как есть; резервные версии остаются доступны, возможные копии в двух днях не удаляются автоматически.

Во всех поисках сначала идут полные точные совпадения, затем буквальное вхождение запроса, затем нечёткие совпадения; внутри группы сохраняется исходный порядок. Нечёткое совпадение: буквы запроса могут идти с пропусками, сохраняя порядок. Регистр не учитывается, «ё» и «е» считаются одинаковыми. Разделы ищутся по названиям и всем идентификаторам crossPeople из шаблона.

Таймстамп формата `YYYY-MM-DD HH:mm:ss` добавляется перед новой записью в «Заметки», когда с последней отдельной строки-таймстампа прошло более 10 полных минут, как в `placeTimestamp.js`. При переносе уже записанного блока новый таймстамп не добавляется. После переноса изменённые файлы сжимаются по правилам Ctrl+`: повторяющиеся пустые строки схлопываются в одну, таймстампы без следующей записи и пустые маркеры вроде «вчера» и «позавчера» удаляются. Общий список маркеров находится в `Скрипты/Настройки/Сжатие дневника.md` внутри хранилища; ObsNotes и скрипт Obsidian читают его заново перед сжатием. Достаточно отредактировать список и дождаться Syncthing. [Формат и поведение при отсутствующих настройках](docs/cleanup-rules.md). Frontmatter, код, callout и якоря сохраняются. Обычное редактирование на прежнем месте не запускает сжатие всего файла.

Служебные строки из `excludeLines` и `excludeContains` не показываются в разделах и не увеличивают счётчики. Исключение для отображения — дневниковые задачи и обычные чекбоксы без тега `#task`: они остаются видимыми и кликабельными, даже если неотмеченная строка включена в список очистки. Неотмеченные задачи не увеличивают счётчики; после отметки учитываются как заполненный факт. Задачи без тега также находятся поиском, позволяют редактировать дополнение и получают дату выполнения из заметки; исходный формат без тега сохраняется. Это правило представления ObsNotes, список очистки Obsidian не меняется. Списки читаются непосредственно из `Скрипты/Modules/Дневник/diaryCleanUtils.js`, без исполнения JS и дублирования списка в приложении. Они перечитываются при подключении, смене даты и кнопкой обновления. Неотмеченные задачи `#task/dairy`/`#task/diary` и пустые Dataview-ключи остаются видимыми для отметки и ввода, но не увеличивают счётчик. Как в JS, не учитываются также отмеченные отрицательные факты «Не ездил на машине» и «не соблюдал диету»; пустые `ФотоПогоды`, `ShortDescr` и `ShortDescrWeek` сохраняют исключение из правила пустого ключа. Значения, начинающиеся после пробелов с «Заполни», считаются незаполненными для любых ключей, включая `ShortDescr` и `ShortDescrWeek`, и не увеличивают счётчики. Подсказки остаются видимыми и редактируемыми; такая же проверка значений используется чеклистом. Счётчик увеличивается один раз на блок, если в нём есть учитываемое содержимое; у родителя учитываются подразделы, при поиске число сохраняется. Отображение хранит исходный блок и смещения: скрытые строки остаются в Markdown и в исходнике редактора.

Часто используемые разделы поднимаются выше в меню «Разделы», перевыборе меток и выборе дополнительных связей для блока/строки. Частота — сумма сохранённых назначений основным и дополнительным разделом; список остаётся полным. При поиске сначала идут полные совпадения, затем буквальные и нечёткие, а частота определяет порядок внутри каждой группы. Порядок отмеченных галочек не меняется. Учитываются переносы, создание сразу в разделе и новые crossPeople/crossOneLine/person/personOneLine; обычная правка, отмена и неудачное сохранение историю не увеличивают. Обычный сбор новых записей в «Заметки» не считается выбором назначения. История накапливается с этой версии, хранится отдельно для каждого хранилища в приватных настройках приложения и сохраняется после перезапуска.

## Рабочие заметки

Если за выбранную дату существует рабочий файл, после «Новостей» появляется **Работа → Основные события**. Приложение проверяет только вычисленный путь `Работа/Daily/Хроника/YYYY/Q/MM-месяц/gggg-W-неделя/YYYY-MM-DD-дд-work.md`, без обхода хранилища. Год и номер недели считаются так же, как для дневниковой заметки. Отсутствующий рабочий файл не создаётся.

Раскройте подраздел, чтобы читать, редактировать и удалять события; `+` создаёт запись сразу в нём. Для переноса из дневника в меню **«Разделы»** найдите «Работа» и выберите **«Работа / Основные события»**. Можно распределить несколько частей редактора между дневником и работой. Рабочая часть имеет одно назначение, без crossPeople, построчных меток и связей частей. При смене даты рабочий файл тоже должен существовать; иначе дата редактора остаётся прежней. Остальные разделы рабочего файла не показываются и сохраняются при записи. Строка-подсказка `*Выделяй жирным шрифтом важное!*` скрывается в «Основных событиях» и не учитывается в счётчиках; в Markdown она сохраняется.

Рабочее назначение записывается и проверяется до удаления исходной записи. Внешние изменения вызывают обычный диалог конфликта; копия рабочей записи сохраняется в «Заметки» дневникового файла исходного дня. Общая кнопка даты по-прежнему выбирает день для всех частей. Разделы любого уровня на главном экране идут без горизонтального отступа; раскрытие показывает иерархию. Старый callout `> [!info]- Работа за YYYY-MM-DD` скрыт в представлении дневника и не учитывается в счётчиках; исходный Markdown сохраняется.

## Шифрование

В настройках выбранного хранилища создайте пароль и четырёхзначный PIN. Новые пароль и PIN вводятся дважды и показываются открыто; несовпадение отмечается красным значком и не позволяет сохранить настройку, без текстовых подсказок. Для уже существующих `secret` нужен **тот же пароль, которым они зашифрованы в Obsidian**; PIN — локальный код доступа ObsNotes. Пароль хранится зашифрованным PIN-кодом. Смена PIN сохраняет пароль; изменение пароля и удаление настройки требуют старый PIN. Смена пароля не перешифровывает прежние записи.

Замок находится рядом с «Разделы», «На строку» и кнопкой человека. Он работает с частью под курсором. Закрытый секрет показан плейсхолдером; нажатие запрашивает PIN и открывает текст. Повторное нажатие шифрует его. После правильного PIN следующие операции обходятся без запроса в течение **трёх минут**, считая от ввода PIN; использование замка не продлевает срок. После перезапуска требуется PIN снова.

Пока редактор открыт, Markdown не меняется, в том числе при уходе приложения в фон. При выходе сохраняется положение замка: открытый — обычный текст, закрытый — совместимый `secret`. Если секрет содержит один текстовый блок, то при чтении и закрытии обратно без правок сохраняется исходный шифротекст и файл вообще не перезаписывается. Пустые строки разделяют и расшифрованный текст на независимые части; замок шифрует только часть под курсором. Родительские связи, собственный якорь и callout остаются метаданными части; содержимое самого секрета шифруется вместе с содержащимися в нём тегами. Внутренний recovery секретного редактора защищён Android Keystore.

Совместимость: AES-256-GCM, 16-байтовые IV и соль, PBKDF2-HMAC-SHA512 с 262144 итерациями, tag 128 бит. В Base64 идут `IV || salt || ciphertext || tag`, в Markdown — одиночные backticks с `secret ` перед Base64. GCM реализован Bouncy Castle, без замены системных провайдеров; это сохраняет 16-байтовый IV из плагина ([ограничение Conscrypt](https://github.com/google/conscrypt/blob/master/common/src/main/java/org/conscrypt/OpenSSLAeadCipher.java), [GCM API](https://downloads.bouncycastle.org/java/docs/bcprov-jdk18on-javadoc/org/bouncycastle/crypto/modes/GCMBlockCipher.html)).

Проверка обеих сторон непосредственно через установленный плагин (только вымышленные данные):

```sh
node tools/check-inline-crypto.cjs /путь/к/vault/.obsidian/plugins/inline-encrypter/main.js
```

По отдельному запросу — изолированная проверка на телефоне, включая настоящий трёхминутный таймер:

```sh
python3 tools/device_encryption.py --serial SERIAL --apk app/build/outputs/apk/debug/app-debug.apk --plugin /путь/к/vault/.obsidian/plugins/inline-encrypter/main.js
```

Она проверяет PIN, настройки, обмен с Obsidian, плейсхолдеры, память после перезапуска и байты/время изменения файла. Оригинальные настройки телефона восстанавливаются побайтово; личные пароли и записи не используются.

## Дневниковые задачи, чеклист и погода

Задачи с `#task/diary` и историческим `#task/dairy` (с подпапками тегов) на главном экране показываются чекбоксами. Квадрат слева переключает выполнение. Тап по тексту открывает многострочное редактирование уже сохранённого значения после `;`, без названия задачи и служебных тегов в поле. Значение можно заменить, дописать или стереть; строки одной части сохраняются через `; `. Непустое значение отмечает задачу выполненной с датой заметки; очистка значения сохраняет название и текущую отметку. Выход без изменений не перезаписывает файл. Пустая строка создаёт независимую часть с собственными назначениями. Метка «Задача: название» обозначает тип назначения; тап позволяет выбрать другое назначение, корзина оставляет значение обычным текстом в разделе. Возврат сохраняет прежнюю прокрутку списка. `✅ YYYY-MM-DD` берётся из даты заметки, снятие отметки убирает дату. Соседние строки, метаданные и якорь сохраняются; другие семейства задач остаются обычными текстовыми записями.

В «Чеклисте» показывается таблица по `dairyCheckList`: заметки, краткое описание, утро/день/вечер, доходы и расходы, местоположение, погода, температура, одежда, настроение, питание, фото, работа, мама, машина и диета. Нажатие на строку открывает соответствующий раздел: раскрывает его родителей и прокручивает к заголовку после раскладки. Уровень вложенности заголовка не влияет на переход. Парные факты машины и диеты проверяются на согласованность; для соблюдённой диеты учитываются калории. Пустые и отсутствующие значения полей считаются незаполненными. Для доходов читаются дата `ДатаПоследнегоЗапускаTOperations` из `Дневник/Служебная_информация.md` и время изменения текущей заметки; для работы — соответствующий `-work.md` по точному пути в `Работа/Daily/Хроника`. Архив не перебирается. Таблица загружается при раскрытии, её данные обновляются при правках дня и по кнопке обновления.

Облачко в заголовке «Погоды» открывает два поля значений: `Погода` и `Температура`. Их можно заполнять вручную. В той же строке выбирается город nuipogoda из списка скрипта или вводится собственный код; последний город запоминается. Кнопка облачка дописывает полученные данные к текущим значениям через `; `, заменяет шаблонные подсказки и не дублирует уже добавленное. Данные выбираются строго по дате, показанной в редакторе, с проверкой года. Одинаковые периоды сводятся к одному значению, разные перечисляются в порядке ночь–утро–день–вечер, как в `weatherVidnoe.js`. При отсутствии данных прежний текст сохраняется. Назад и уход в фон сохраняют форму через общий журнал и проверку конфликтов. Долгий сетевой запрос не блокирует редактирование или выход; устаревшие результаты после закрытия игнорируются.

## Совместимость и границы

- Шаблон читается с телефона. Из него берутся заголовки, идентификаторы crossPeople и `include_sections`. Если очищенный раздел отсутствует в существующем дне, восстанавливаются его заголовок, недостающие родители и crossPeople-представление. Задачи и поля из шаблона повторно не добавляются.
- DataviewJS и Tasks-запросы не исполняются Android-клиентом. Приложение самостоятельно показывает crossPeople, person, oneLine и связи; остальные скрипты, запросы, ссылки и frontmatter сохраняются в исходном файле. Пользовательские fenced code blocks доступны как текст.
- В текущем Obsidian-скрипте `crossPeopleUtils.js` значения тегов разбираются регулярным выражением только из букв. Поэтому шаблонные `Пер1`, `Пер2`, `Пер3`, `Пер4` не предлагаются как теги: их не смог бы показать Obsidian. В соответствующие разделы можно перемещать блоки напрямую. Скрипты и заметки хранилища при разработке не изменялись.
- Корневые блоки с якорями и локальные ссылки вида `[[#^id]]` нельзя переносить между днями: существующие адреса должны оставаться действительными. Дополнения с явной ссылкой на файл переносить можно. Между разделами одного дня корни переносятся вместе с callout.
- Поиск входящих связей корневого блока идёт в отдельном фоновом потоке с результатами и счётчиком проверенных дней. «Закрыть» или Назад отменяет дальнейшее чтение; редактор и очередь сохранения не блокируются. Отмена проверяется между папками и файлами; уже начатый запрос Android-провайдера может завершиться после закрытия окна, его результаты игнорируются. Разобранный архив не накапливается в памяти. Поиск дополнений охватывает `Дневник/Хроника`; файл корня из явной ссылки читается напрямую. Структура разделов обновляется при повторном подключении хранилища.
- Главный экран проверяет внешние изменения каждые 5 секунд, пока открыт. Редактор сохраняет снимок оригинала: внешние правки приводят к конфликту, а не к молчаливой перезаписи. Открытие, навигация, обновление и выбор даты назначения используют вычисленный путь `Дневник/Хроника/YYYY/Q/MM-месяц/gggg-W-неделя/YYYY-MM-DD-дд.md`. Архив для этих действий не сканируется.

## Сохранение и восстановление

`VaultRepository` сравнивает полное содержимое перед записью, сохраняет журнал с версиями до и после, записывает целевой файл первым и проверяет результат чтением. После прерывания приложение продолжает операцию, только если все участвующие файлы соответствуют версии до или после. Неизвестное внешнее состояние останавливает восстановление. SAF не предоставляет атомарную транзакцию между файлами или compare-and-swap с Syncthing: остаётся короткое окно гонки между последним чтением и записью.

В настройках, в раскрывающемся «Восстановление», можно повторить незавершённую операцию или принять текущие внешние файлы, сохранив текст редактора и резервные версии. После принятия возможны дубликаты блока в двух днях — сначала проверьте оба файла. История последних 10 операций находится в приватной папке приложения `files/journals/<vault-id>/backup-*.bin`; активная операция — `pending.bin`. Файлы содержат UTF-8 строки с длиной в байтах (big-endian int): число изменений, затем для каждого путь, версия до и версия после. Для установленной debug-сборки папка доступна через `adb shell run-as ru.obsnotes`. Удаление приложения удалит текст восстановления редактора и резервные версии.

Доступ к выбранной папке сохраняется через [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files). Разрешение Internet используется только для явного запроса погоды: nuipogoda получает код города и дату, без содержимого заметок. Заметки и резервные версии не отправляются приложением в GitHub или другие сетевые сервисы; синхронизацией независимо занимается Syncthing.

Многострочный ввод доступен также для значений Dataview и дополнений к задачам: строки одной части сохраняются через `; `, а пустая строка создаёт обычную независимую часть с собственными разделами, тегами и связями. Названия ключей и задач защищены и показаны в метках: `Ключ::` и значок квадрата с галочкой и название задачи. Тап по метке меняет назначение, корзина снимает его и оставляет значение обычным текстом в физическом разделе. Выбор другого ключа или задачи переносит значение с обычным дописыванием через `; `. При выходе без изменений файл не перезаписывается. Несколько исходных Dataview-ключей имеют отдельные части; пустые значения сохраняют ключи.

В одном поле можно набрать несколько частей, разделив их пустыми строками. Под полем одновременно показаны их метки: основной раздел (белый), дополнительные разделы (фиолетовые), построчные метки (цвет соответствующей строки) и связь. Заголовки и начало текста частей в панелях не повторяются; панель части под курсором всегда выделена тонкой белой рамкой, даже если часть одна. Пустая панель остаётся видимой после удаления всех меток. Тап по свободной области панели переносит курсор в конец её текстовой части, фокусирует поле и открывает клавиатуру; нужный курсор становится видимым при прокрутке. Переход работает и для пустых панелей. Метки и корзины по-прежнему выполняют свои действия. Общая широкая кнопка даты меняет день для **всех** частей. Ниже расположены общие «Разделы» и «На строку», применяющиеся к части/строке под курсором; нажатие уже выбранной метки меняет её независимо от курсора. Цвета строк уникальны во всём редакторе. Кнопка **«Связать»** действует на часть под курсором и позволяет выбрать внутреннего или внешнего родителя; отдельной галочки нет, пустые метки связей скрыты. Каждое нажатие «Связать» добавляет ещё одного родителя, например третья → первая и третья → вторая. Событие, уже связанное с родителем, тоже доступно в общем списке кандидатов: при выборе оно становится промежуточным корнем, сохраняя прежние связи. Все связи видны отдельными метками: тап заменяет только выбранную связь, корзина удаляет только её. «Сделать корневым» сохраняет собственных родителей части. Корзина метки «Корень» убирает его якорь и callout, а также все ведущие ссылки на него в текущем файле; другие дни и обычные ссылки внутри текста не меняются. Номера и начало текста видны только в меню выбора родителя. Циклы отклоняются, идентичность и связи частей сохраняются при вставках и перезапуске; промежуточный корень сохраняется в совместимом формате Obsidian.

Если итоговое состояние редактора совпадает с исходным, выход не записывает заметку и не запускает сжатие или журнал — в том числе когда правки текста, меток, разделов и связей были сделаны и затем возвращены обратно. Положение курсора и состояние меню не считаются изменениями. В чеклисте заполнение любого раздела «Перекус 1»…«Перекус 4» окрашивает «Перекусы» зелёным; такой же результат даёт `dairyCheckList.js` в хранилище.

Пробелы и табуляция в конце строки сохраняются во время набора и перед скрытым якорем корневого блока: можно сразу продолжать строку следующим словом.

## Совместное редактирование и порядок записей

Свайп вправо выбирает обычную текстовую запись, повторный снимает выбор. Можно выбрать записи в разных разделах и через crossPeople: проекция указывает на тот же оригинал. Выбор сохраняется при поиске, даже если выбранные скрылись. Справа от ObsNotes появляются две квадратные кнопки: число выбранных и крестик. Кнопка с числом открывает всю группу в одном поле с пустыми строками и отдельными панелями меток, в том числе скрытые поиском выбранные записи. Пока есть выбор, тап по обычной записи или её стрелке добавляет её в выбор либо снимает выделение; снятие последнего выделения возвращает обычный режим. Крестик снимает весь выбор. Поиск и раскрытие разделов сохраняются; после выхода из режима выбора обычный тап снова открывает отдельный редактор. Выделение обновляется на месте, без пересоздания главного экрана. Задачи и значения Dataview открываются своими обычными редакторами.

Удаление пустой строки объединяет части. Основной раздел верхней остаётся основным, совместимые остальные назначения становятся дополнительными; построчные теги и родители сохраняются. При объединении корня с его дочерней частью связь между ними убирается, а прежний якорь и callout корня сохраняются независимо от порядка частей. Другие входящие ссылки продолжают вести к объединённому тексту. При двух разных существующих якорях редактор сохраняет состояние и просит сначала снять лишнюю корневую роль. Закрытые шифрованные части перед объединением нужно расшифровать замком; редактор сохраняет каждый исходный payload до явного изменения. Несовместимые назначения также остаются доступны для исправления в панелях, без записи неполного результата.

Долгое нажатие начинает перетаскивание записи выше или ниже других исходных записей её раздела. Соседние разделы и проекции не принимают перемещение. Ссылки и теги движутся вместе с записью; заголовки и промежутки между исходными позициями сохраняются. На краях экрана работает автопрокрутка. Левый свайп по-прежнему вызывает подтверждение удаления.

Сохранение группы проверяет версии всех участвующих файлов и использует один журнал. Неизменённые записи не переписываются; при внешнем конфликте текст остаётся в редакторе. Встречные переносы между файлами выполняются отдельно, чтобы назначение всегда было проверено до удаления источника.

Подробности устранённых повторных вычислений и воспроизводимые замеры: [производительность](docs/performance.md).

## Разработка и выпуск

Для HTML погоды используется jsoup 1.24.1 с `desugar_jdk_libs_nio` 2.1.5 для Android.

Нужны JDK 21, Android SDK 36.1 и build-tools; версии Gradle и зависимостей согласованы с локальным ObsFit. Укажите путь SDK в `local.properties`:

```properties
sdk.dir=/home/aborunov/Android/Sdk
```

```sh
./gradlew :core:test :app:lintDebug
python3 -B -m unittest discover -s tools -p 'test_*.py'
python3 tools/release.py
```

Версия имеет вид `0.<среднее>.<последнее>`. Масштабная доработка повышает среднее число и обнуляет последнее (`0.2.4 → 0.3.0`); мелкое исправление или документация повышает последнее (`0.2.4 → 0.2.5`). Старшее число пока всегда 0. Android `versionCode` каждый выпуск увеличивается на 1 независимо от этих чисел.

Релизный скрипт последовательно проверяет собственные тесты, тесты ядра, собирает подписанную debug APK для личной установки, запускает lint и проверку 16 КБ. Только после успешных проверок он атомарно публикует APK в `dist/`, обновляет `SHA256SUMS` и оставляет три последние APK. Это локальный выпуск, не публикация в Google Play. APK, кеши, локальные настройки и ключи игнорируются Git.

Проверки на устройстве выполняются только по отдельной просьбе пользователя. Для явно запрошенной автоматической UI-регрессии на разблокированном телефоне (дополняет тесты ядра):

```sh
python3 tools/device_day_navigation.py --serial SERIAL --apk app/build/outputs/apk/debug/app-debug.apk
```
