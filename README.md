# ObsNotes

Личный Android-клиент для ежедневных заметок Obsidian. Android 13 и новее. Тёмная палитра Things и компактные элементы интерфейса по образцу ObsFit. Приложение работает непосредственно с Markdown в выбранной папке; Syncthing синхронизирует её независимо от приложения.

## Установка и работа

1. Установите APK из `dist/` и выберите **корневую папку хранилища** через системный диалог Android. Подтвердите доступ на чтение и запись. В папке должны находиться `Дневник/Хроника` и `Шаблоны/Шаблон дневниковой записи.md`.
2. Дата открывает календарь; стрелки переключают дни. Под датой есть поиск разделов по названиям, идентификаторам и именам Dataview-ключей, включая вложенные. Например, «Температура» находит раздел «Погода». Кнопка календаря «Сегодня» в верхней панели рядом с настройками возвращает к сегодняшнему дню одним нажатием; в редакторе она тоже находится сверху. Переход к отсутствующему дню оставляет текущую дату, документ и редактор, показывает красное «Заметка не найдена» и сохраняет отзывчивость кнопок. **Приложение не создаёт дневниковых файлов и не исполняет Templater.**
3. Кнопка `+` в строке «Заметки» открывает редактор. Главный экран показывает верхние разделы; подразделы появляются только внутри раскрытого родителя. Счётчик родителя включает вложенные блоки и перекрёстные отображения. Стрелки раскрывают раздел и текст блока. Нажатие на текст открывает редактирование оригинала, включая блоки, показанные через crossPeople. Свайп влево предлагает удалить запись с подтверждением; отмена ничего не меняет. Для перекрёстного отображения удаляется его оригинал. Если удаляется корневой блок, подтверждение сообщает о связях.
4. «Разделы» открывает общий список назначения: первый выбранный пункт получает текст, последующие разделы добавляются в `crossPeople`. Галочки запоминают порядок нажатий; удаление первого пункта продвигает следующий. Основная метка белая, дополнительные — фиолетовые. Нажатие на название выбирает и сразу закрывает меню; галочки позволяют набрать несколько пунктов, подтверждение находится сверху. Все подразделы доступны всегда. Задачи и Dataview-поля существующего дня можно выбрать первыми. Поиск получает фокус и открывает клавиатуру сразу после открытия выбора. Однострочный текст дописывается в задачу или значение поля через `; `. Многострочный текст нельзя выбрать для переноса в Dataview-ключ. У выбранной задачи можно снять «С текстом»: сохранятся только отметка выполнения и дата, исходный переносимый текст уберётся из прежнего места. Ключи существующих Dataview-полей показаны в метках отдельных полей ввода; редактируются только значения.
5. Кнопка даты в редакторе открывает список **существующих дней** от даты исходной заметки назад. Строка содержит дату и значение `ShortDescr`. Читаются порции по 14 календарных дат, следующие подгружаются при прокрутке; отсутствующие файлы пропускаются. Если вся порция пуста, следующую можно загрузить кнопкой внизу списка. Выберите раздел назначения и нажмите векторную кнопку сохранения в верхней панели. Целевой файл записывается и проверяется до удаления исходного блока. После сохранения открывается день назначения.
6. «Разделы» и «На строку» позволяют выбрать несколько идентификаторов; теги записываются в совместимом формате `#crossPeople/ЛенаПокупки` или `#crossOneLine/Утро`. Для строки используется положение курсора. Кнопка человека добавляет `#person/` или `#personOneLine/` перед существующим именем, если оно найдено; поддерживаются Лена, Аня, Вика, Мама. Служебные теги скрыты из поля ввода; имя человека остаётся обычным текстом. Метки представлены под полем и удаляются своей векторной кнопкой. Метки всего блока идут первыми и окрашены фиолетовым, без слова «блок». Только строки с `crossOneLine` и `personOneLine` получают цвет шрифта; соответствующие метки окрашены так же, без номера строки. Фон поля не меняется. `crossPeople` и `person` для всего блока не окрашивают текст. Вставка обычных строк сохраняет привязки и цвета отмеченных строк; удаление имени снимает его метку.
7. «Сделать корневым» добавляет стабильный `^event-…` и callout `outLinkInfo`. «Связать» показывает корни и обычные блоки текущего дня, как Ctrl-8: обычный выбранный блок становится корневым при сохранении. Кнопка цепочки проверяет ведущую wiki-ссылку либо сочетание якоря с callout `outLinkInfo`. Без этих признаков сразу показывает, что связей нет, не обращаясь к файлам. Ведущая ссылка открывает только указанный корневой файл. Для сохранённого корня сначала показываются дополнения текущего дня, затем подгружаются найденные дополнения из архива. Служебный callout, якорь и ведущая ссылка на корень скрыты из поля и сохраняются при редактировании. Связь с корнем показана отдельной меткой под полем.

Назад, «Сегодня» и уход из приложения сохраняют текущее содержимое без подтверждения. Отдельных черновиков и кнопок для работы с ними нет. Пустая новая запись не добавляется; очистка существующего текста удаляет его исходный блок, кроме защищённого корня с якорем. При ошибке записи текст остаётся в редакторе; прерванная запись восстанавливается при следующем запуске. Снимки для восстановления хранятся внутри приложения и не заменяют проверку внешних изменений. Приложение всегда остаётся в портретной ориентации.

Нажатие на выбранную метку открывает замену с отмеченным текущим значением. Замена основного раздела или допраздела сохраняет порядок остальных назначений. Построчная метка сохраняет исходную строку и цвет независимо от положения курсора. Нажатие на имя сразу заменяет назначение; для перекрёстной метки галочками можно изменить несколько идентификаторов и применить их сверху. Нажатие на метку корня открывает перевыбор родительского события.

Если файл изменился извне и сохранение конфликтует, появляется выбор: **«Сохранить копию»**, **«Отменить правку»** или **«Остаться»**. Копия добавляет видимый текст отдельной записью в «Заметки» исходного дня, сохраняя текущие внешние данные. В копии нет служебных тегов и связей, якорей и callout; названия редактируемых Dataview-полей остаются обычными подписями, чтобы не создать повторные активные ключи. Отмена открывает свежий файл без записи. Если конфликт возник посреди переноса, эти действия принимают уже записанные части как есть; резервные версии остаются доступны, возможные копии в двух днях не удаляются автоматически.

Во всех поисках сначала идут полные точные совпадения, затем буквальное вхождение запроса, затем нечёткие совпадения; внутри группы сохраняется исходный порядок. Нечёткое совпадение: буквы запроса могут идти с пропусками, сохраняя порядок. Регистр не учитывается, «ё» и «е» считаются одинаковыми. Разделы ищутся по названиям и всем идентификаторам crossPeople из шаблона.

Таймстамп формата `YYYY-MM-DD HH:mm:ss` добавляется перед новой записью в «Заметки», когда с последней отдельной строки-таймстампа прошло более 10 полных минут, как в `placeTimestamp.js`. При переносе уже записанного блока новый таймстамп не добавляется. После переноса изменённые файлы сжимаются по правилам Ctrl+`: повторяющиеся пустые строки схлопываются в одну, таймстампы без следующей записи и пустые маркеры вроде «вчера» и «позавчера» удаляются. Frontmatter, код, callout и якоря сохраняются. Обычное редактирование на прежнем месте не запускает сжатие всего файла.

## Дневниковые задачи, чеклист и погода

Задачи с `#task/diary` и историческим `#task/dairy` (с подпапками тегов) на главном экране показываются чекбоксами. Нажатие на чекбокс или текст отмечает действие; удержание текста открывает обычный редактор. `✅ YYYY-MM-DD` всегда берётся из открытой заметки, включая прошлые дни, и исправляет прежнюю неправильную дату. Снятие отметки убирает дату выполнения. Отметка и обновление файла извне сохраняют позицию прокрутки главного экрана. Остальные метаданные и якорь задачи сохраняются. Другие семейства задач остаются обычными текстовыми записями.

В «Чеклисте» показывается таблица по `dairyCheckList`: заметки, краткое описание, утро/день/вечер, доходы и расходы, местоположение, погода, температура, одежда, настроение, питание, фото, работа, мама, машина и диета. Нажатие на строку открывает соответствующий раздел: раскрывает его родителей и прокручивает к заголовку после раскладки. Уровень вложенности заголовка не влияет на переход. Парные факты машины и диеты проверяются на согласованность; для соблюдённой диеты учитываются калории. Пустые и отсутствующие значения полей считаются незаполненными. Для доходов читаются дата `ДатаПоследнегоЗапускаTOperations` из `Дневник/Служебная_информация.md` и время изменения текущей заметки; для работы — соответствующий `-work.md` по точному пути в `Работа/Daily/Хроника`. Архив не перебирается. Таблица загружается при раскрытии, её данные обновляются при правках дня и по кнопке обновления.

Облачко в заголовке «Погоды» открывает два поля значений: `Погода` и `Температура`. Их можно заполнять вручную. В той же строке выбирается город nuipogoda из списка скрипта или вводится собственный код; последний город запоминается. Кнопка облачка дописывает полученные данные к текущим значениям через `; `, заменяет шаблонные подсказки и не дублирует уже добавленное. Данные выбираются строго по дате, показанной в редакторе, с проверкой года. Одинаковые периоды сводятся к одному значению, разные перечисляются в порядке ночь–утро–день–вечер, как в `weatherVidnoe.js`. При отсутствии данных прежний текст сохраняется. Назад и уход в фон сохраняют форму через общий журнал и проверку конфликтов. Долгий сетевой запрос не блокирует редактирование или выход; устаревшие результаты после закрытия игнорируются.

## Совместимость и границы

- Шаблон читается с телефона. Из него берутся заголовки, идентификаторы crossPeople и `include_sections`. Если очищенный раздел отсутствует в существующем дне, восстанавливаются его заголовок, недостающие родители и crossPeople-представление. Задачи и поля из шаблона повторно не добавляются.
- DataviewJS и Tasks-запросы не исполняются Android-клиентом. Приложение самостоятельно показывает crossPeople, person, oneLine и связи; остальные скрипты, запросы, ссылки и frontmatter сохраняются в исходном файле. Пользовательские fenced code blocks доступны как текст.
- В текущем Obsidian-скрипте `crossPeopleUtils.js` значения тегов разбираются регулярным выражением только из букв. Поэтому шаблонные `Пер1`, `Пер2`, `Пер3`, `Пер4` не предлагаются как теги: их не смог бы показать Obsidian. В соответствующие разделы можно перемещать блоки напрямую. Скрипты и заметки хранилища при разработке не изменялись.
- Корневые блоки с якорями и локальные ссылки вида `[[#^id]]` нельзя переносить между днями: существующие адреса должны оставаться действительными. Дополнения с явной ссылкой на файл переносить можно. Между разделами одного дня корни переносятся вместе с callout.
- Поиск входящих связей корневого блока идёт в отдельном фоновом потоке с результатами и счётчиком проверенных дней. «Закрыть» или Назад отменяет дальнейшее чтение; редактор и очередь сохранения не блокируются. Отмена проверяется между папками и файлами; уже начатый запрос Android-провайдера может завершиться после закрытия окна, его результаты игнорируются. Разобранный архив не накапливается в памяти. Поиск дополнений охватывает `Дневник/Хроника`; файл корня из явной ссылки читается напрямую. Структура разделов обновляется при повторном подключении хранилища.
- Главный экран проверяет внешние изменения каждые 5 секунд, пока открыт. Редактор сохраняет снимок оригинала: внешние правки приводят к конфликту, а не к молчаливой перезаписи. Открытие, навигация, обновление и выбор даты назначения используют вычисленный путь `Дневник/Хроника/YYYY/Q/MM-месяц/gggg-W-неделя/YYYY-MM-DD-дд.md`. Архив для этих действий не сканируется.

## Сохранение и восстановление

`VaultRepository` сравнивает полное содержимое перед записью, сохраняет журнал с версиями до и после, записывает целевой файл первым и проверяет результат чтением. После прерывания приложение продолжает операцию, только если все участвующие файлы соответствуют версии до или после. Неизвестное внешнее состояние останавливает восстановление. SAF не предоставляет атомарную транзакцию между файлами или compare-and-swap с Syncthing: остаётся короткое окно гонки между последним чтением и записью.

В настройках, в раскрывающемся «Восстановление», можно повторить незавершённую операцию или принять текущие внешние файлы, сохранив текст редактора и резервные версии. После принятия возможны дубликаты блока в двух днях — сначала проверьте оба файла. История последних 10 операций находится в приватной папке приложения `files/journals/<vault-id>/backup-*.bin`; активная операция — `pending.bin`. Файлы содержат UTF-8 строки с длиной в байтах (big-endian int): число изменений, затем для каждого путь, версия до и версия после. Для установленной debug-сборки папка доступна через `adb shell run-as ru.obsnotes`. Удаление приложения удалит текст восстановления редактора и резервные версии.

Доступ к выбранной папке сохраняется через [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files). Разрешение Internet используется только для явного запроса погоды: nuipogoda получает код города и дату, без содержимого заметок. Заметки и резервные версии не отправляются приложением в GitHub или другие сетевые сервисы; синхронизацией независимо занимается Syncthing.

## Разработка и выпуск

Для HTML погоды используется jsoup 1.24.1 с `desugar_jdk_libs_nio` 2.1.5 для Android.

Нужны JDK 21, Android SDK 36.1 и build-tools; версии Gradle и зависимостей согласованы с локальным ObsFit. Укажите путь SDK в `local.properties`:

```properties
sdk.dir=/home/aborunov/Android/Sdk
```

```sh
./gradlew :core:test :app:lintDebug
python3 -B -m unittest discover -s tools -p 'test_*.py'
python3 tools/release.py
```

Релизный скрипт последовательно проверяет собственные тесты, тесты ядра, собирает подписанную debug APK для личной установки, запускает lint и проверку 16 КБ. Только после успешных проверок он атомарно публикует APK в `dist/`, обновляет `SHA256SUMS` и оставляет три последние APK. Это локальный выпуск, не публикация в Google Play. APK, кеши, локальные настройки и ключи игнорируются Git.

Автоматическая UI-регрессия на разблокированном телефоне (дополняет тесты ядра):

```sh
python3 tools/device_day_navigation.py --serial SERIAL --apk app/build/outputs/apk/debug/app-debug.apk
```

Нужен ранее выданный SAF-доступ к `Documents/ObsNotes-EditorCheck`. Скрипт отказывается заменять существующую папку, создаёт только вымышленные заметки, проверяет поиск ключа, переход к вложенному разделу и сохранение позиции после отметки и внешнего изменения. Исходные настройки и состояние редактора восстанавливаются побайтово, тестовая папка удаляется; приложение остаётся остановленным.

Дополнительная проверка реального хранилища **только чтением**:

```sh
./gradlew :core:classes
javac -cp core/build/classes/java/main -d /tmp/obsnotes-check tools/CheckVault.java
java -cp core/build/classes/java/main:/tmp/obsnotes-check CheckVault /path/to/vault
```

Она проверяет сохранность содержимого при тождественной замене каждого блока, чтение структуры шаблона, восстановление разделов в памяти и сохранение тегов, строк их привязки и якорей при редактировании чистого текста. Содержимое заметок не выводится.

Предметная логика, состояние редактора, разбор Markdown, план сохранения и журнал находятся в `core` без Android-зависимостей. `app/ui` содержит экраны и общие компоненты. `MainActivity` управляет переходами и фоновыми операциями; `SafVaultStorage` реализует только доступ к документам Android. Соблюдаются [отступы системных панелей и клавиатуры](https://developer.android.com/develop/ui/views/layout/edge-to-edge).

Проверки на подключённом телефоне и их границы описаны в [DEVICE_TESTS.md](DEVICE_TESTS.md).
