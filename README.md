# ObsNotes

Личный Android-клиент для ежедневных заметок Obsidian. Android 13 и новее. Тёмная палитра Things и компактные элементы интерфейса по образцу ObsFit. Приложение работает непосредственно с Markdown в выбранной папке; Syncthing синхронизирует её независимо от приложения.

## Установка и работа

1. Установите APK из `dist/` и выберите **корневую папку хранилища** через системный диалог Android. Подтвердите доступ на чтение и запись. В папке должны находиться `Дневник/Хроника` и `Шаблоны/Шаблон дневниковой записи.md`.
2. Дата открывает календарь; стрелки переключают дни. Удержание даты возвращает к сегодняшнему дню. Отсутствующий день показывается без возможности записи. **Приложение не создаёт дневниковых файлов и не исполняет Templater.**
3. Кнопка `+` в строке «Заметки» открывает редактор. Заголовки разделов показывают число собственных и перекрёстных блоков; стрелки раскрывают раздел и текст блока. Нажатие на текст открывает редактирование оригинала, включая блоки, показанные через crossPeople.
4. Под текстом выберите раздел поиском или из списка. В том же списке доступны задачи и Dataview-поля существующего дня. Однострочный блок добавляется в задачу с отметкой выполнения и датой либо в значение ключа через `; `. Шаблонные подсказки значения заменяются.
5. Кнопка даты в редакторе выбирает **существующий прошлый день**. Выберите раздел назначения и нажмите векторную кнопку сохранения в верхней панели. Целевой файл записывается и проверяется до удаления исходного блока. После сохранения открывается день назначения.
6. «Допразделы» и «На строку» позволяют выбрать несколько идентификаторов; теги записываются в совместимом формате `#crossPeople/ЛенаПокупки` или `#crossOneLine/Утро`. Для строки используется положение курсора. Кнопка человека добавляет `#person/` или `#personOneLine/` перед существующим именем, если оно найдено; поддерживаются Лена, Аня, Вика, Мама. Теги видны в тексте и удаляются обычным редактированием.
7. «Сделать корневым» добавляет стабильный `^event-…` и callout `outLinkInfo`. «Связать» показывает корни и обычные блоки текущего дня, как Ctrl-8: обычный выбранный блок становится корневым при сохранении. Кнопка связи показывает сохранённые входящие и исходящие связи среди дневниковых файлов. Служебный callout и якорь скрыты из текстового поля и сохраняются при редактировании.

Назад оставляет локальный черновик. Он доступен из верхней панели главного экрана и настроек; новый блок не перезаписывает незавершённый черновик. При повороте экрана редактор восстанавливается. Для каждого выбранного хранилища хранится отдельный черновик вместе с исходными версиями файлов.

Таймстамп формата `YYYY-MM-DD HH:mm:ss` добавляется перед новой записью в «Заметки», когда с последней отдельной строки-таймстампа прошло более 10 полных минут, как в `placeTimestamp.js`. При переносе уже записанного блока новый таймстамп не добавляется.

## Совместимость и границы

- Шаблон читается с телефона. Из него берутся заголовки, идентификаторы crossPeople и `include_sections`. Если очищенный раздел отсутствует в существующем дне, восстанавливаются его заголовок, недостающие родители и crossPeople-представление. Задачи и поля из шаблона повторно не добавляются.
- DataviewJS и Tasks-запросы не исполняются Android-клиентом. Приложение самостоятельно показывает crossPeople, person, oneLine и связи; остальные скрипты, запросы, ссылки и frontmatter сохраняются в исходном файле. Пользовательские fenced code blocks доступны как текст.
- В текущем Obsidian-скрипте `crossPeopleUtils.js` значения тегов разбираются регулярным выражением только из букв. Поэтому шаблонные `Пер1`, `Пер2`, `Пер3`, `Пер4` не предлагаются как теги: их не смог бы показать Obsidian. В соответствующие разделы можно перемещать блоки напрямую. Скрипты и заметки хранилища при разработке не изменялись.
- Корневые блоки с якорями и локальные ссылки вида `[[#^id]]` нельзя переносить между днями: существующие адреса должны оставаться действительными. Дополнения с явной ссылкой на файл переносить можно. Между разделами одного дня корни переносятся вместе с callout.
- Поиск связей читает существующие дневниковые файлы в фоне; на большом хранилище первый поиск может занять время. Данные вне `Дневник/Хроника` не индексируются. Структура разделов обновляется при повторном подключении хранилища.
- Главный экран проверяет внешние изменения каждые 5 секунд, пока открыт. Редактор сохраняет снимок оригинала: внешние правки приводят к конфликту, а не к молчаливой перезаписи. Кнопка обновления также перечитывает список дней.

## Сохранение и восстановление

`VaultRepository` сравнивает полное содержимое перед записью, сохраняет журнал с версиями до и после, записывает целевой файл первым и проверяет результат чтением. После прерывания приложение продолжает операцию, только если все участвующие файлы соответствуют версии до или после. Неизвестное внешнее состояние останавливает восстановление. SAF не предоставляет атомарную транзакцию между файлами или compare-and-swap с Syncthing: остаётся короткое окно гонки между последним чтением и записью.

В настройках, в раскрывающемся «Восстановление», можно повторить незавершённую операцию или принять текущие внешние файлы, сохранив черновик и резервные версии. После принятия возможны дубликаты блока в двух днях — сначала проверьте оба файла. История последних 10 операций находится в приватной папке приложения `files/journals/<vault-id>/backup-*.bin`; активная операция — `pending.bin`. Файлы содержат UTF-8 строки с длиной в байтах (big-endian int): число изменений, затем для каждого путь, версия до и версия после. Для установленной debug-сборки папка доступна через `adb shell run-as ru.obsnotes`. Удаление приложения удалит локальные черновики и резервные версии.

Доступ к выбранной папке сохраняется через [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files). У приложения нет сетевых разрешений; заметки и резервные версии не отправляются в GitHub или приложение синхронизации самим ObsNotes.

## Разработка и выпуск

Нужны JDK 21, Android SDK 36.1 и build-tools; версии Gradle и зависимостей согласованы с локальным ObsFit. Укажите путь SDK в `local.properties`:

```properties
sdk.dir=/home/aborunov/Android/Sdk
```

```sh
./gradlew :core:test :app:lintDebug
python3 -B -m unittest discover -s tools -p 'test_*.py'
python3 tools/release.py
```

Релизный скрипт последовательно проверяет собственные тесты, тесты ядра, собирает подписанную debug APK для личной установки, запускает lint и проверку 16 КБ. Только после успешных проверок он атомарно публикует APK в `dist/`, обновляет `SHA256SUMS` и оставляет три последние APK. Это локальный выпуск, не публикация в Google Play. APK, кеши, локальные настройки и ключи игнорируются Git.

Дополнительная проверка реального хранилища **только чтением**:

```sh
./gradlew :core:classes
javac -cp core/build/classes/java/main -d /tmp/obsnotes-check tools/CheckVault.java
java -cp core/build/classes/java/main:/tmp/obsnotes-check CheckVault /path/to/vault
```

Она проверяет сохранность содержимого при тождественной замене каждого блока, чтение структуры шаблона и восстановление разделов в памяти. Содержимое заметок не выводится.

Предметная логика, состояние редактора, разбор Markdown, план сохранения и журнал находятся в `core` без Android-зависимостей. `app/ui` содержит экраны и общие компоненты. `MainActivity` управляет переходами и фоновыми операциями; `SafVaultStorage` реализует только доступ к документам Android. Соблюдаются [отступы системных панелей и клавиатуры](https://developer.android.com/develop/ui/views/layout/edge-to-edge).
